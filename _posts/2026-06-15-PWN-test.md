## Stack
Ghi từ addresse cao hơn xuống adresse thấp hơn. 
Khi call 1 function : 
```assembly
push rbp
mov rbp, rsp
sub rsp, 0x1337
```

```
Higher addresses
+------------------+
| return address   |  <-- [rbp+0x8]
+------------------+
| saved rbp        |  <-- [rbp]
+------------------+
| local variables  |  <-- [rbp-...]
+------------------+
| rsp              |  <-- [rsp-0x1337]
+------------------+
Lower addresses
```

## Buffer

Buffer không có direction, tùy vào cách viết code mà chương trình sẽ lưu giá trị từ cao xuông thấp hoặc ngược lại. 
Ví dụ của việc buffer ghi giá trị từ lower -> higher. Cách viết này khá phổ biến. Và thực ra khi tạo 1 array, (ở đây là char buf[5]), memory sẽ lưu lần lượt được lưu từ lower adresse tới higher adresse : 
```c
#include <stdio.h>

int main() {
    char buf[5];

    for (int i = 0; i < 5; i++) {
        buf[i] = 'A' + i;
        printf("the addresse of the buff %i is : %p\n",i,buf[i]);
        /* buf[0] : lowest adresse
        the addresse of the buff 0 is : 0x41
        the addresse of the buff 1 is : 0x42
        the addresse of the buff 2 is : 0x43
        the addresse of the buff 3 is : 0x44
        the addresse of the buff 4 is : 0x45
            buf[4] is highest adresse
        */
    }  

    return 0;
}
```
Tuy nhiên cũng có trường hợp ngược lại,data trong buffer được ghi từ higher -> lower. holy shit ! 
```c
#include <stdio.h>

int main() {
    char buf[5];
    char *p = &buf[4];

    *p-- = 'A';
    *p-- = 'B';
    *p-- = 'C';
    *p-- = 'D';
    *p-- = 'E';
    for (int i = 0; i < 5; i++) {
        printf("the addresse of the buff %i is : %p\n",i,buf[i]);
    }
    /*
        the addresse of the buff 0 is : 0x45
        the addresse of the buff 1 is : 0x44
        the addresse of the buff 2 is : 0x43
        the addresse of the buff 3 is : 0x42
        the addresse of the buff 4 is : 0x41
    */
    return 0;
}
```

## lea instruction

```assembly
lea rax,[rbp-0x1337]
```
Thằng này lúc đầu tôi hiểu nhầm, tôi nghĩ nó giống mov, nó dereference giá trị được lưu trong addresse được ghi bên tay phải và lưu vào registry bên tay trái. Nhưng thực tế nó chỉ lưu giá trị adresse trong registry 



## printf and read 

Về printf, [link sau đây ghi khá cụ thể](https://www.cs.uaf.edu/2017/fall/cs301/lecture/09_25_printf.html)
Tóm lại là khi viết printf trong C
```c
int val = 5;
printf("value in integer : %d",val);
```
Thì nó sẽ tương ứng như sau : 
```assembly
mov r8,5 
mov rdi,formatStr ; first argument: format string
mov rsi,; second argument (for format string below): integer to print
mov al,0 ; magic for varargs (0==no magic, to prevent a crash!)
call printf
```
Về read, theo như [link sau](https://blog.rchapman.org/posts/Linux_System_Call_Table_for_x86_64/), nó có 3 arguments (int fd,char *buffer, size_t count). Các argument này lần lượt được lưu vào rdi,rsi,rdx. (size_t : unsigned int data type)

## Vào việc

![read input](/assets/images/pwn/read_function.png)
Ở đây ta có : 
```assembly
read(0,(rpb-0x90),[rbp-0x98])
```
trong đó :
- fd = 0 : input 
- char *buffer = (rpb-0x90) : điểm bắt đầù trong memory sẽ để read input ghi vào
- size_t count =  [rbp-0x98] : max size

Vậy là ta có điểm bắt đầù $rpb-0x90. 
Xa hơn chút, để gọi được funtion win, ta có 
```assembly
mov     eax, dword [rbp-0x14] 
cmp     eax, some_random_val 
jne     addresse of function win 
```
Để gọi được vào, chương trình sẽ so sánh giá trị được ghi (dạng dword) bắt đầu từ $rbp-0x14 với 1 giá trị ngẫu nhiên. Vậy nên : 
- padding : ($rbp - 0x14) - ($rbp - 0x90)
Rồi cứ thế ghi giá trị random yêu cầu vào là xong.
